# 团队知识承载方案选型

团队需要同时解决长期知识沉淀、Agent 可读、执行规则稳定和对外展示四类需求。单一工具难以兼顾所有目标，因此需要明确不同载体的职责边界。

LLM Wiki 适合保存长期判断、背景和决策依据，可被 Agent 持续读取；Skill 适合封装稳定执行规则和工具链；飞书文档适合人工阅读、评审和案例展示；聊天记录只适合临时回看，不应作为正式知识底座。

选型标准包括沉淀能力、Agent 可读性、协作成本和展示效果。综合比较后，推荐采用分层方案：Wiki 保存长期知识，Skill 承载执行约束，飞书文档展示结果，聊天记录不进入正式沉淀。

关键风险是知识与规则混写后难以维护，以及多个入口缺少统一索引。下一步需要建立统一目录，并为 Wiki、Skill 和飞书文档定义明确的更新责任。
